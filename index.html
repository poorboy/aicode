aicode is a lightweight AI task batch system. It manages projects, task groups and tasks on the web, turning “prompt + project directory” into a task queue, creating sessions and sending prompts on the codetools (Go rewrite of opencode) engine, streaming AI output live in the browser, and auto-exporting Markdown session archives when tasks finish.

Features

Every piece you need to batch-drive AI coding

From task orchestration and engine scheduling to live output, failure self-healing, knowledge retrieval and container builds — every step already runs in one program.

Task orchestration & serial execution

Three-level objects: project / task group / task; executed strictly serially by order — this version runs only 1 task at a time (concurrency is not configurable), with batch operations and task templates.

  • Task = title + prompt template ($TASKDES substituted)
  • A project directory can link any number of tasks
  • One-click “Start / Stop”, per-session abort

SSE real-time output

Open the chat window while a task runs to watch the AI’s text, tool calls and reasoning over SSE in real time; step in to keep the conversation going, then auto-save a Markdown session archive on completion.

  • One engine instance per project dir; same-dir tasks reuse it
  • Stuck detection / auto-continue / activity-silence grace
  • Process safety: only terminates instances it started

Automatic backup-proxy failover

Tasks can define an ordered “backup proxy list”: when the primary hits rate limits, runs out of quota, times out on the first reply or stalls mid-stream, it switches to the next immediately and continues in the same session, so nothing already produced is lost.

  • Providers merged at startup; switching only PATCHes the session model
  • Falls back to exponential backoff when all proxies fail
  • Proxy quota stats recorded by the model actually in effect

HTTP proxy pool & rate-limit retry

The “HTTP proxy list” does not switch models — it just sends requests through the proxies in order; when a single request hits 429/5xx or a network error the engine retries with the next proxy, forming two layers of self-healing with model-level retries.

  • Supports http:// https:// socks5://
  • Rate-limit retry: 30s×2ⁿ exponential backoff, capped at 5 minutes
  • Task list shows “backup N” / “HTTP proxy N” badges

Code graph (CodeGraph)

Per user × project index files and query store; background indexing jobs, status stats, symbol search, impact analysis and a graph view let both AI and humans locate change scope fast.

  • /api/codegraph/* and the /tk variant
  • Poll / stop / delete jobs; index results are traceable

Container build environment

When the program runs in a container without a toolchain, it executes go build / npm run build / pytest in one-shot containers via Docker Engine, sharing the directory via bind mount and writing artifacts back to the source dir.

  • lin_env container pool and buildenv quick builds
  • Incremental output polling, sync / async runs, artifact browsing & download

Skills & skill marketplace

A global skill directory data/skills/; import / export / delete / preview zips in the web UI, with installs and removals synced to running engine instances instantly; can connect to the SkillHub marketplace.

  • Built-in skill templates like op-task and container-build
  • Skill changes need no instance restart

Multi-user & licensing

Multi-user data isolation, admin / regular-user roles, login and auth-code protection, x-tk programmatic tokens, plus non-disableable mandatory licensing and license-server auto-activation.

  • Projects, knowledge collections and instances isolated per user
  • Two paths: license file or external license server

Operations & cluster

Online self-update (binary + web static assets), cluster master reporting, license-server client, run logs and proxy quota stats — multi-node deployments stay centrally managed.

  • /api/update* self-update (update_key auth)
  • cluster.enabled status reporting and proxy calls

File browser & terminal

Browse / upload / download / preview / edit / delete files from the project directory root (server guards against path traversal), with a built-in web bash terminal so you need not SSH in for ops and debugging.

  • shell.enabled toggles the terminal page
  • Edit files online with the Monaco editor
Workflow

Six steps to complete one round of batch AI coding

From creating a project to getting the session archive, the whole flow closes the loop in one web console.

  1. 01

    Create a project

    One project maps to one disk directory; register it via the web form or /api/projects, with a directory availability check.

  2. 02

    Create groups & tasks

    Task groups handle serial orchestration; a task takes a title and prompt template and picks its project, group and execution order.

  3. 03

    Configure AI & self-healing

    Pick the primary proxy model, optionally a backup proxy list and HTTP proxy list, plus rate-limit retry and stuck-detection parameters.

  4. 04

    Start running

    Click “Start”: the system schedules tasks by concurrency and spins up a dedicated codetools instance per project directory.

  5. 05

    Watch & intervene live

    The SSE chat window shows text / tool calls / reasoning; pause, continue the conversation or stop generation at any time.

  6. 06

    Archive & search

    Finished tasks auto-export Markdown session logs; results can feed the CodeGraph index for later tasks to reuse.

Quick Start

Start in three steps, up and running in ten minutes

Build from source, run directly, or compile in a container env — pick whichever suits you.

# Requirements: Go ≥ 1.23; Node ≥ 18 to build the frontend
# Linux / macOS
./script/setup.sh

# Windows
script/setup.bat

# Or one-shot build (auto-injects version info)
sh ./bld.sh            # output to exe/
cd prog && sh bld.sh    # output to prog/exe/
# Start (aicode.exe on Windows; aicode on Linux/macOS)
cd prog/exe && ./aicode.exe

# Open the console in a browser
http://127.0.0.1:8090

# First start auto-generates data/cfg/cfg.yaml; edit port / auth code /
# aicode.base_port etc. Frontend dev mode (hot reload):
cd prog/lai_coding_web && npm run dev   # default 3000, /api proxied to 8090
# Create a project
curl -X POST http://127.0.0.1:8090/api/projects \
  -H "Content-Type: application/json" \
  -d '{"name":"myapp","directory":"/path/to/myapp"}'

# Create a task (link a project; many tasks can point to one project)
curl -X POST http://127.0.0.1:8090/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Generate API docs","prompt":"Write a README for the backend package",
       "project_id":"project_xxx","order":1}'

# Run serially / run one group / check status
curl -X POST http://127.0.0.1:8090/api/tasks/run
curl -X POST http://127.0.0.1:8090/api/groups/group_xxx/run
curl http://127.0.0.1:8090/api/tasks/status
# When the program runs in a container that has no Go/Node toolchain:
# compile via the backend container env (container-build skill)
TK="<programmatic access token>"
BASE="http://127.0.0.1:8090"

# Build in the auto-go env (artifacts go to /out, i.e. the source dir)
curl -s -X POST -H "x-tk: $TK" -H "Content-Type: application/json" \
  -d '{"env_id":"auto-go","directory":"/work/myproj",
       "command":"go build -o /out/app ."}' \
  "$BASE/api/tk/linenv/runs?sync=1"

# Long tasks: submit async, then poll incremental output / fetch artifacts
curl -s -H "x-tk: $TK" "$BASE/api/tk/linenv/runs/$RUN_ID?since=0"
curl -s -H "x-tk: $TK" "$BASE/api/tk/linenv/artifacts?path=build"

FAQ

A few things people ask before starting

Will multiple tasks pointing at the same project directory interfere with each other?

No. Tasks in the same directory share one engine instance (reusing its port), while different directories each start their own; scheduling is strictly serial — this version runs only 1 task at a time (concurrency fixed at 1, not configurable).

Do model rate limits (HTTP 429 / FreeUsageLimitError) fail the task outright?

By default, no. On a rate limit it re-sends a short system nudge in the same session with exponential backoff to continue: interval retry_backoff × 2ⁿ (starts at 30s, capped at 5 minutes per wait), up to retry_count times (default 8, hard cap 12, ~27 minutes total window). If a backup proxy list is set, it first switches to the next proxy immediately.

What is the difference between the “backup proxy list” and the “HTTP proxy list”?

The backup proxy list switches the model / provider (moves to the next model config when the primary is unavailable); the HTTP proxy list does not change the model — it merely sends requests through different forward proxies, and the engine retries with the next proxy on a rate limit or network error.

The program runs in a container without Go/Node — how do I compile projects?

With container builds enabled, run compile/test commands via /api/tk/linenv/runs in preset env containers (auto-go / auto-node / auto-python-pytest …): the project dir is bind-mounted into the container and artifacts written to /out land back in the source dir, with sync full output or async incremental polling, and browsing/download via the artifacts API.

Does this landing page need a build step?

No. prog/webset/ is a zero-dependency pure static site (HTML + CSS + vanilla JS); just open index.html in a browser, or host it on any web server or under this program’s static/ directory.

Can mandatory licensing be turned off?

No. Without a valid license file (data/license.key) business features are locked and the frontend shows the activation screen. Activate either by the classic standalone license-file flow or by configuring a license server for auto-activation.
